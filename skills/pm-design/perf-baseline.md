# 提速基线（三产物·回归对比参照）

> 建立日期：2026-09-14。**最近一次复测：2026-10-13**（① ④ 重测 + 补 ⑤ ⑥ + ② 由估算改为实测）。
> 用途：记录「原型 / PRD / 代码结构 / 交付件」各层提速的**实测与估算幅度**，作为以后回归对比的基准——改了装配器/骨架/生成器后，用文末「复测方法」重跑，数字明显退化即视为性能回归。
> 标注约定：**〔实测〕**=本机 `Measure-Command` 真跑；**〔估算〕**=按机制推算、随功能数/内容量浮动，非承诺值。

---

## ① 生成原型（改一处 → 重装配）

| 指标 | 优化前 | 优化后 | 幅度 |
|---|---|---|---|
| 单次墙钟（纯装配 vs 带浏览器布局/保真闸） | 4485ms | **85ms** | **约 53×** 〔实测 09-14〕 |
| 带体检闸的全量装配（64 页 / 交付件 14.7MB） | — | **9.4s** | 〔实测 10-13〕 |
| 单次墙钟（对比旧「装配 + make-offline + 截图」全跑） | ~20–50s | 85ms | **约 250–600×** 〔估算·取决于截图页数〕 |
| 单次 token（读/改整份大 HTML vs 只改 project-data 几行） | ~1.9MB 原型 ≈ 50 万 token | ≈ 1–2 千 token | **约 100–500×** 〔估算〕 |

根因：生成原型本就 85ms，慢的是「每改一次都多跑了交付才需要的验收（闸/离线/截图）」。迭代默认 `assemble-prototype.js … --fast`。

## ② 生成 PRD（标注/内容）

| 手段 | 幅度 | 说明 |
|---|---|---|
| 复用固定件·只写业务槽位 | **实测 9.5%**〔实测 10-13·**原估"20–30%"偏高 2–3 倍，已作废**〕 | 见下方实测明细 |
| 多功能并行（仅 Claude Code） | **墙钟 ≈ ÷N** 〔估算·含调度开销〕 | 一次圈 N 个 → 扇 N 个子 agent 各写一个 fp；Cursor/Codex 退串行、不计。**墙钟取决于 AI 思考时间，脚本量不出来，只能估** |
| 增量只生成改动项 | **改 1/共 M ≈ ÷M** 〔机制必然·无需实测〕 | 只跑新圈/改过的 fp（`anno-ai-queue`），已生成的不重跑 |

**「复用固定件」实测明细**（2026-10-13·样本 = 真实 PRD 一份、10 个功能点、16,662 字符）：

| 固定件 | 出现 | 占字符 |
|---|---|---|
| 操作日志固定句 | 7 次 | 399 |
| 提示消息表头 | 3 次 | 87 |
| 通知 4 列表头 | 0 次 | 0 |
| 表格分隔行 | 19 次 | 247 |
| 七节小标题（`• 前置条件：` 等） | 70 次 | 490 |
| 「用例规则」标题 | 10 次 | 200 |
| 空节（`• 消息通知：无。`） | 17 次 | 153 |
| **合计** | | **1,576 字符 = 全文 9.5%**，平均每个功能点 158 字符 |

> 诚实边界：① 字符数 ≠ token 数（同量级，不等价）；② 这份样本的消息通知多为「无。」，**业务通知多的 PRD 固定件占比会更高**（4 列表格会放大）；③ 只测了一份 PRD，换样本会浮动。
> 结论：固定件仍值得复用（**格式永远对**是主要收益），但**"省 20–30%"这个数字不成立**，按 ~10% 说。

## ④ 交付件重建（改完 → 用户打开的那个离线文件）

`rebuild-deliverable.ps1` = 全量装配（含体检闸）→ make-offline → 逐页自检。

**2026-09-16 首测分解（37 页）**：

| 阶段 | 优化前 | 优化后 | 说明 |
|---|---|---|---|
| ① 全量装配（含体检闸） | 10.4s | 10.4s | 未动 |
| ② **离线化（内联 Vue+EP）** | **188.3s** | **0.9s** | **约 200×**〔实测〕——原来每次从 unpkg 重下 5 个资产（1.75MB）；改为读随包 `vendor/` |
| ③ 交付件逐页自检（37 页） | 28.9s | 28.9s 全量 / **3.5s 增量** | 增量=只验改动涉及的页（`-Pages "issuing"`） |
| **合计（交付·全量）** | **198.1s** | **40.8s** | **约 4.9×**〔实测〕 |
| **合计（迭代·增量）** | **198.1s** | **14.4s** | **约 13.8×**〔实测 `-Pages "issuing"`〕 |

> 上表 ③ 是 09-16 的**串行**数。2026-10-13 起自检默认 **4 进程并行**，同件实测 46.0s → **18.7s**，见下方复测。

**2026-10-13 复测（同一项目已长到 63 页 / 交付件 14.7MB）**：

| 阶段 | 实测 | 单位成本 | 判定 |
|---|---|---|---|
| ① 全量装配（含体检闸） | **9.4s** | — | 与 09-16 的 10.4s 持平，**无回归** |
| ③ 全量逐页自检（串行） | **46.0s** | **0.73s / 页**（63 页） | 09-16 为 0.78s/页（28.9s÷37）——**每页成本没变，总时长纯粹随页数线性增长，无回归** |
| ③ 全量逐页自检（**并行 4 进程·现默认**） | **18.7s** | 0.30s / 页 | **2.5×**〔实测·同机同件·两次都是 63 页全覆盖 0 红 exit=0〕|

**③ 这 0.73s/页 花在哪（2026-10-13 查明）**：
`deliverable-verify-gate.js` 原来只起**一次** headless Chrome，但**每一页都 `Page.navigate` 重新加载整份 14.7MB 交付件**——重新解析 HTML、重跑内联的 Vue + Element Plus、重新挂载，然后按 120ms 粒度轮询直到 `#app` 有内容。
**为什么不能"加载一次、页内切页"**：骨架在 `createApp({ setup(){ const _q = new URLSearchParams(location.search) …` 处**只在挂载时读一次 `?page=`**，`go(id)` 是 setup 内的闭包、**没有暴露到 window**，CDP 够不着。

**已做的优化（方向 B·2026-10-13）**：闸新增 `--jobs N`（**默认自动最多 4 进程**，`--jobs 1` 退回串行）。父进程只负责分片 + 汇总、自己不开浏览器；每个子进程 `--shard i/N` 自己开一个 headless Chrome、各占独立端口（9760+2i），只验下标 `idx%N===i` 的那些页。
**没有弱化验证语义**：每页仍是真实冷加载、仍是独立浏览器实例；①新旧检查仍只在父进程跑一次。
**覆盖面自证**：并行与串行两次都是 **63 页、页名去重后数量一致、0 红**（防"分片算错导致静默少验"）。
四个调用点（`rebuild-deliverable.ps1` ×3、`quick.ps1`）都走默认值，**自动吃到加速，无需改动**。
> 还想更快只剩方向 **A**（骨架暴露 `window.__go`，加载 1 次 + 页内切页，预计约 10s），但要 bump 标准件版本 + 重注入所有原型 —— **未做，需用户同意**。

**增量自检的安全边界**：`rebuild-deliverable.ps1 -Pages "<页id,页id>"` / `deliverable-verify-gate.js … --pages a,b`
**不传就是全量**（默认永远安全）；增量跑完会打印「⚠️ 这不等于"做完了"，交付前必须再跑一次全量」；
`--pages` 指定了不存在的页会**判红**（防止拼错页名→静默少验→以为验过了）。

**离线化的根因**：②与「改了什么、改了多少」完全无关——空跑一次也是 188 秒，纯粹是重复下载同一批固定版本的文件。
**全新机器实测**：删光本机所有缓存后首次离线化 **8.4s**，全部从随包 `vendor/` 读取、**全程不联网**（原来新机器第一次必须联网等 188 秒，断网不可用）。
**防回退**：机器闸 `qa/vendor-shipped-gate.js`（已挂 deliver-gate）卡死「vendor 齐全 + 两个使用方先读它 + 版本标记一致」。

## 复测方法（回归时重跑）

```powershell
# ① 原型：纯装配(--fast) vs 带浏览器闸，各测墙钟。<pd> 换成任一 project-data.json
$pd = "<你的 project-data.json>"; $qa = "<工具目录>\skills\pm-design\qa"
$fast = Measure-Command { node "$qa\assemble-prototype.js" $pd "$env:TEMP\_pt.html" --fast | Out-Null }
$full = Measure-Command { node "$qa\assemble-prototype.js" $pd "$env:TEMP\_pt2.html" | Out-Null }
"① 纯装配 --fast: {0} ms · 带闸: {1} ms · 幅度: {2}×" -f [int]$fast.TotalMilliseconds, [int]$full.TotalMilliseconds, [math]::Round($full.TotalMilliseconds/$fast.TotalMilliseconds,0)

# ④ 交付件：离线化 + 全量逐页自检（算出"每页成本"才有可比性，总时长会随页数增长）
Measure-Command { & "<工具目录>\skills\pm-design\make-offline.ps1" -InputHtml "$env:TEMP\_pt2.html" -OutputHtml "$env:TEMP\_p_off.html" }
Measure-Command { node "$qa\deliverable-verify-gate.js" "<交付件.html>" $pd }
```

**基线值**
- ① `--fast` ≈ 85ms（09-14 本机）；带闸全量 ≈ 9.4–10.4s。`--fast` 涨到几百 ms、或带闸涨到 >15s → 查装配器/闸是否引入新重活。
- ④ 离线化 ≈ 0.9s（随包 vendor 命中）。**涨到几十秒以上 = vendor 没命中、又在联网下载**。
- ④ 逐页自检 **≈ 0.72s/页**。**比的是每页成本，不是总秒数**——页数变了总秒数一定变。单页成本涨到 >1.2s/页 → 查交付件是否变大、或轮询/渲染路径是否变慢。

模拟全新机器：把 `skills/pm-design/vendor` 临时改名再跑离线化（应自动联网重下并回填 vendor）。

②③ 无稳定单命令基线（随功能数/内容量变）：② 的「固定件占比」用本档实测方法（正则统计固定件字符 ÷ 全文字符）复算；③ 不是「脚本变快」，是「少了一道必经工序」。
