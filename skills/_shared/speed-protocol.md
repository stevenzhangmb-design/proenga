## 一、三条产线 ×（从 0 生成 / 中途改）的快路

**原则一句话**：**从 0 走"一条命令出骨架 + 模板/固定件填充"，中途改走"只碰受影响的那一小块 + 只验那一块"。两头都不许从零手敲、不许全量重跑。**

### 1. 原型

| | 快路 | 禁 |
|---|---|---|
| **从 0 生成** | `p.js init` + `add-list/add-form/add-view` 或 `build`（一个 spec 出整页）；mock 数据用 `mockgen` 按列名生成；多页**并行扇出**（各写各文件，零冲突）再合并 | 禁一行行手写几千行 JSON；禁串行一页一页磨 |
| **中途改** | 只改 `project-data.json` 里对应那几行 → `p.js … render <页>`（约 1.5s，**文字**报结构，不截图）；一批改完才 `rebuild-deliverable.ps1 -Quick` 重建一次 | 禁读/改大 HTML 产物；禁每改一处就跑离线化、跑全套闸、跑截图 |

### 2. PRD

| | 快路 | 禁 |
|---|---|---|
| **从 0 生成** | 固定件直接沿用 `annotation-templates.md`（操作日志表头+固定说明语、查询类固定句、提示消息表头、通知 4 列表头），AI 只写业务槽位；多个功能点**并行扇出**，一个 agent 写一个 fp | 禁从空白开始写每一节；禁串行写完一个再写下一个 |
| **中途改** | 只改 `prd-data.json` 里那个 fp 的 `_draft_*` 字段 → 走 anno-server 增量队列 `anno-ai-queue` **只重生成这一个功能点**；`.md`/`.docx` 由 anno-server 确定性生成 | **禁重写整篇 PRD**；禁 AI 手写大 md 文件；禁机械预生成业务内容（伤质量） |

### 3. 代码

| | 快路 | 禁 |
|---|---|---|
| **从 0 生成** | `dev-codegen`：`derive-from-prototype` 推 data_model → `emit-scaffold-*` 出骨架 → `emit-*` 出各层；契约/DDL/i18n 走模板 | 禁从零手敲工程；禁一个文件一个文件地想 |
| **中途改** | 只重跑**受影响的那一层**的 emitter（改了字段→只重出 contract+backend；改了页面→只重出 frontend）；验证只跑该层的 smoke | 禁 `emit-all` 全量重出；禁改一处重跑整套验证 |

## 二、行为纪律（三条产线通用 · 这是上次翻车的那条）

1. **同一个动作连续失败 2 次 → 立刻停**，不许第 3 次重试同一条路（同一脚本、同一参数、同一种绕法）。
2. **停下来先说话**：一句话讲清「卡在哪、已有什么证据、打算怎么办」。**不许闷头试**。
3. **分清「任务」和「取证手段」**：改没改完、验没验过＝**任务**；截图、起浏览器、量尺寸＝**取证手段**。
   **手段失败不等于任务失败** —— 已有机器实测证据时，手段就该放弃，不许为补一张图烧光时间。
4. **工具坏了换路或直说**（浏览器连不上、窗口尺寸不对、CDP 抽风），不在坏工具上死磕；
   实在拿不到证据，老实写进「还没做」让用户决定。
5. **做长活要报进度**：超过两三步没出声，用户就不知道你在干嘛。中间发一句「在做 X，还差 Y」。
6. **攒批**：同一轮里的多处改动合并成**一次**重建、**一次**验收，不要一处一轮。

## 三、和别的规则的关系

- 与 `pm-design/SKILL.md` §改原型提速铁律、`pm-design/perf-baseline.md` 同一套：
  那边给**命令和实测数**，这里给**不许把时间花在哪**。
- 与 `feedback_only_verified_certain_answers`（别空口保证）配套：那条管"必须验"，这条管"**别为了验把自己绕进去**"。
- 与「交付自查铁律」不冲突：**该验还得验**，只是验的方式可以换、不能无限重试；
  换不到就写进「还没做」，不许假装验过。
