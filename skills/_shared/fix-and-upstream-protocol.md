# 修复与回流协议（Fix & Upstream Protocol · 随包·跨工具）

> **两个读者**：
> · **A 部分 → 给 AI**（任何工具里的 AI 修 bug 时必须遵守的纪律）
> · **B 部分 → 给用户**（可直接粘进 README 的说明）

---

## A. 给 AI：修复纪律（强制）

### A1. 修之前：先确认"应该是什么样"，再动手
1. 读 [`acceptance-checklist.md`](./acceptance-checklist.md) —— 那里写着每个功能**必达的行为**（红线一~四）。
2. 跑 `node skills/pm-design/qa/deliver-gate.js` 定位——**闸红了才知道坏在哪**；闸全绿但用户报了现象，说明**闸有盲区**（见 A5）。
3. **禁靠猜**。这轮真实教训：一个"导出分享版弹不出框"的 bug，连猜三次（视口 / DOM 结构 / 滚动）都没中，**最后靠在浏览器里实地量元素坐标才看清真因**。**能测就别猜。**

### A2. 修复必须落在源头层，不是只改当前原型
- bug 在 `skills/**`（规则 / 标准件 / 闸）→ **改源头**，别只改手边那个原型文件。
- 改完自问三句：① 我改的是源头层还是只改了当前原型？② 它随包吗？③ 有机器证据证明新原型/新用户也获得了修复吗？

### A3. 改了标准件（`components/annotation-layer.html` / `prototype-skeleton.html`）三步不能少
1. **改标准件**
2. **bump 版本**（`__ANNO_LAYER_VERSION__`），并在版本注释里**写清根因和正确写法**（下一个人读代码就懂）
3. **把新标准件重新注入所有已有原型**（`node qa/inject-latest-anno-layer.js <原型> <输出>`）
   > ⚠️ 只改 skill 不重注入，**老原型里仍是旧副本、bug 还在**。⑰漂移闸会抓到，别忽略它。
4. 跑 `deliver-gate.js` 全绿。

### A4. 🏛 每个修复必须配一道闸或静态断言（防重新引入）
> **修好一个 bug ≠ 它不会回来。** 必须留下机器防线：谁（任何人、任何 AI、任何工具）把它改回去，**闸立刻红、禁交付**。

**范例**（2026-07-09 导出分享版真 bug）：
- 根因：`showSaveFilePicker` 被放在 `await fetch` 之后 → 用户手势过期 → 框弹不出 → 抛 `AbortError` → 被误判成"用户取消" → 永远提示"已取消保存"。
- 修复：拆 `_pickSaveHandle`（先弹框）+ `_writeOut`（后写入），顺序改成 **①弹框 → ②取内容 → ③写入**。
- **配的防线**：在 `share-export-behavior-gate.js` 里加**静态断言**——`_pickSaveHandle` 必须出现在 `fetch` 之前，顺序反了即红。

### A5. 🏛 禁用"假实现 / 硬编码"绕过真实约束来验收
这一轮里，**"闸判绿但东西是坏的"发生了四次**，共同点都在这条：

| 闸 | 为什么判绿却是坏的 |
|---|---|
| 导出分享版行为闸 | **注入了假 picker**，绕开了浏览器真实的"用户手势"限制 → 真 bug 隐身 |
| 设计令牌闸 | 只验主色/警告/分页 config，**不验筛选区宽/sticky/页签** → 规范改了骨架没跟上，照样绿 |
| 注入回路闸 | 用**硬编码像素** `top>140` 过滤候选 → 样式一改按钮跑到 138，被误排除 → 假失败 |
| 原型↔标准件漂移闸 | 锚点**写死旧函数名** → 函数改名后闸自己先坏 |

**规矩**：
- 若必须用假实现（如假 picker、fixture、mock），**必须另配一条静态断言兜住真实约束**（如"picker 调用必须在 fetch 之前"）。
- 尽量**按结构判定**（closest/类名/契约），少用像素阈值和写死的标识符。
- **闸只能抓它被教会的东西**——闸绿 ≠ 没问题；用户报了现象而闸绿，**先怀疑闸有盲区**。

### A6. 交付前
- `deliver-gate.js` **全绿**才准交付；涉 UI 改动**必须截图眼验**（原生弹框等 headless 验不了的，**必须让用户亲自点一次**）。
- **禁说"保证/焊死了/彻底解决"**——给可复现的证据（闸绿截图、负向测试），让人不必信你也能自己复现。

### A7. 修完必须回流上游（见 B 部分）
本地修复只救本机。**不回流 = 上游还是坏的 = 别人和新安装的继续中招。**

## B. 给用户：遇到问题怎么办（可直接粘进 README）

### B1. 先自检，别猜
```bash
node skills/pm-design/qa/deliver-gate.js
```
- **红了** → 输出会告诉你坏在哪一环。
- **全绿但你确实遇到问题** → 说明这个问题**闸还没覆盖到**。请照 B3 报给我们，我们会**补一道闸**，而不只是修一次。

对照 `skills/_shared/acceptance-checklist.md` 可以看到每个功能**本该是什么行为**。

### B2. 你可以自己修（这是本地包的优势）
这套东西是**你机器上的普通文件**（规则 `.md` + 标准件 `.html` + 闸 `.js`），你的 AI 工具能读、能改、能跑闸验证。改完存盘，**你本地就已经修好了，下次不会再犯**。

⚠️ **一个必须知道的细节**：如果 bug 在**标准件**（`annotation-layer.html`）里，光改 skill 不够——**已经画出来的老原型里内嵌着旧副本**。要再跑一次：
```bash
node skills/pm-design/qa/inject-latest-anno-layer.js <你的原型.html> <输出.html>
```
（新画的原型不用管，自动就是修好的。⑰漂移闸也会提醒你哪些原型还内嵌着旧标准件。）

### B3. ⚠️ 修完请务必回流，否则你的修复会丢
**你的修改只在你这一台机器上，作者完全不知道。**

请二选一：
- **提 Pull Request**（推荐）——你的修复和测试直接被合并，一次修复、所有人受益。
- **提 Issue / 直接告诉作者**——作者在上游修好后发版。

### B4. 升级方式，以及为什么别长期分叉
| 安装方式 | 升级 | 本地改动 |
|---|---|---|
| `git clone` | `git pull` | **会冲突**，需要你手动合并 |
| 下载 zip | 重新下载覆盖 | **会被直接覆盖丢失** |

> **所以规矩是**：本地改是**应急**；改完尽快提 PR 或告诉作者。等官方发版后 `git pull`，用官方版覆盖掉你的临时修改。
> **别长期本地分叉**——否则以后每次更新都打架。

### B5. 我们对每个修复的承诺
每修一个 bug，我们会**同时加一道机器闸或静态断言**把根因钉死。所以同一个 bug **不会以同样的方式回来**——不是靠"我们会小心"，是靠**闸红了就不让交付**。
