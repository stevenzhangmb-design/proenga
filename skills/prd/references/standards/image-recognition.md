# 图片识别标准块

> 统一规范 AI 在编写 PRD 时对用户提供的 UI 截图 / 原型图的识别动作。  
> 引用方：`SKILL.md`、`prd-template-structure.mdc`、`prd-prompt-template-common.md`。  
> 核心目标：不漏字段、不猜字段、不做业务二次判断、冲突留痕。

## 一、总原则

- 图片优先：有截图 → 字段骨架从图提取，不要求用户在文字区重复列字段名。
- 以实际截图为准：图上显示什么就记什么，不做"是否有业务意义"的二次判断。
- 不得臆测：图片看不到的信息（唯一性、业务校验、默认值业务含义、错误提示文案、字段级权限、字段级触发时机）必须从文字补充取；没有文字补充则进"待确认项"。
- 冲突留痕：任何不确定项一律进"待确认项"，禁止用常识、经验或同类项目默认值补全。
- 绑定优先：当一次对话中提供**多张**截图、或截图数量/顺序与文字菜单难以一一对应时，用户必须按**第二节**给出「图片编号 ↔ 菜单路径 ↔ 功能点」绑定；缺失绑定时，AI 必须先问最少必要问题补齐绑定表，再进入字段提取与 PRD 挂接。

## 二、用户图片绑定输入（强制模板）

**适用：**用户上传 ≥2 张 UI 截图；或单张截图但需声明「同图多状态 / 多 Tab / 多弹窗」；或截图与「菜单路径：功能点」文字无法一眼对齐。

**输入方式：**推荐先在同一条消息里粘贴绑定表，再上传截图，保证模型先读到「编号 ↔ 菜单 ↔ 功能点」映射。

**铁律：**

- 每张对外使用的截图必须有**全局唯一**图片编号（如 `IMG-01`），全对话不重复、不跳号重排。
- 绑定关系必须写到**功能点粒度**：`菜单路径：功能点` 中的冒号规则与 PRD「结构解析铁律」一致——**冒号前仅菜单路径**，**冒号后仅功能点**；禁止把功能点写成菜单、禁止擅自改路径。
- 若用户只给菜单路径、未写功能点，且图上无法唯一判断归属功能点，必须进「待确认项」，不得猜。

**用户填写模板（推荐原样复制填空）：**

```text
【图片绑定】
图片编号规则：IMG- 两位序号递增（IMG-01、IMG-02…）

| 图片编号 | 系统视图 | 菜单路径：功能点 | 页面类型（列表/表单/弹窗/详情） | 备注（可选：Tab 名、状态、入口按钮） |
|---|---|---|---|---|
| IMG-01 | <OMS/WMS/…> | <完整菜单路径：具体功能点> | <…> | <…> |
| IMG-02 | <…> | <…> | <…> | <…> |

【同图多切片（可选）】
若一张长图被裁成多段上传，请说明裁切顺序与重叠关系：
- 原图逻辑顺序：IMG-01（上）→ IMG-02（中）→ …
- 重叠区说明：<有/无，若有请描述重叠字段>
```

**AI 对照动作（机械执行）：**

- 先做「绑定表完整性检查」：每张图是否都有编号行；`菜单路径：功能点` 是否同时存在；页面类型是否足以判断字段来源（列表 vs 表单）。
- 再做「逐图识别」：每张图的识别段落**首行**必须复述绑定：`绑定：IMG-xx = <菜单路径：功能点>`，避免串图。
- 任何绑定缺项、串图风险、或「一张图对应多个未列出的功能点」，一律先补问或进「待确认项」。

## 三、通用识别清单（适用所有 UI 截图）

AI 看到任意 UI 截图时，按下表逐项识别；元素存在才列出，不存在直接跳过。

| 识别要素 | 要求 |
|---|---|
| 字段名 | 精确到页面标签文字，不改写、不缩写 |
| 控件类型 | 输入框 / 文本域 / 下拉 / 多选下拉 / 级联 / 日期 / 日期范围 / 单选 / 多选 / 开关 / 上传 |
| 必填标记 | 红 `*` / "必填"文字 / 红框 / 红色竖线 → 任一出现即判为必填 |
| 默认值 | 以实际截图为准（§3.1.5）：有默认值（可见选中项/预填值/单选默认选中如"无物流发货"/只读默认显示如"-"）→ 按图记录默认值；无默认值但有占位提示（灰字"请输入..."、"--请选择--"）→ 记占位原文（一字照图）；无默认值且无占位 → 记"空"/"无"。不做二次判断。 |
| 按钮 | 列出所有主次按钮名称与位置（行内 / 批量 / 底部） |
| 列表字段 | 仅取表头列名，不取数据行 |
| 操作列 | 列表最右侧"操作"列内的按钮单独列出 |
| 查询条件 | 列表上方筛选区的字段名 + 控件类型 + 默认值（按本表第 4 行规则） |
| Tab / 折叠面板 | 分组列出归属字段；非默认激活项也要列出；**Tab/分组标题名一字不易取自截图**（不得改为同义词，如"基础信息" ≠ "基本信息"）；**截图无 Tab/分组特征时不加 PRD 分块标题**（详见 prd-template-structure.mdc §3.1.6） |
| 禁用态字段 | 单独标注"不可编辑" |

## 四、禁止行为（反模式）

- ❌ 把占位提示当"真实业务默认值"（无默认值时占位照原文记入默认值列，但它不是业务预设值，§3.1.5）
- ❌ 把列表数据行当字段（只看表头）
- ❌ 漏识别折叠面板 / Tab 下的字段
- ❌ 漏识别最右侧"操作"列
- ❌ 自行补齐图上没有但"同类 PRD 常见"的字段
- ❌ 把禁用态字段当可编辑字段
- ❌ 把表单中的"说明文字""副标题"当字段
- ❌ 对图上出现的默认值做二次业务判断（如觉得"全部"无意义就不记录）
- ❌ **臆造字段规范分块标题**（如截图无"基础信息""税务信息"等分组却在 PRD 加 `**1、基础信息**` `**4、税务信息**` 段；详见 §3.1.6）
- ❌ **改写截图 Tab/分组真实名称**（如截图 Tab 为"基础信息"却在 PRD 改为"基本信息"等同义词）

## 五、输出顺序（强制）

AI 识别完图片后，必须按下列顺序输出：

0. 图片绑定表（按需）：若触发第二节适用场景，必须先输出用户填写并经 AI 复核后的绑定表（可原样复述用户表格，也可在缺字段时先补问补齐后再输出）；若无需绑定，则本步写一行 `无。`。
1. 图片识别结果：逐图一段，用 Markdown 表格列出识别到的字段 / 按钮 / Tab 等要素（如实记录截图内容）。
2. 图片归档清单：固定五段文本，用 `-` 连接（便于检索与对账）：`图片编号 - 系统视图 - 菜单路径 - 功能点 - 图片用途`；其中 `菜单路径` 与 `功能点` 必须与用户绑定表一致分列，不得合并成模糊一句。
3. 待确认项：若存在冲突、模糊、缺失，按第六节模板列出。
4. 合理化建议：若识别结果存在可优化点，按第七节模板列出（不改变识别结果，仅作为补充建议）。
5. PRD 正文：字段规范的"字段骨架"必须引用自第 1 步的识别结果，不允许重新臆造。

### 五·1 输出归属铁律

**第 0~4 步（图片绑定表 / 识别结果 / 归档清单 / 待确认项 / 合理化建议）属于对话辅助输出**，仅在 AI 与用户的对话消息中呈现，**严禁**写入 PRD 正文文件（.md 归档稿）。**仅第 5 步「PRD 正文」**进入 PRD 文件。

具体禁止行为：
- 严禁在 PRD 文件中出现 `### 本批截图识别摘要(...)` 一类标题段。
- 严禁把 `**图片绑定表**`、`**图片归档清单**`、`**待确认项**`、`**合理化建议**` 段落写入 PRD 正文。
- 严禁把图片识别表（图编号-菜单-页面类型-备注 等）作为附录写入 PRD 文件。
- 若需要在 PRD 内引用具体图片，仅在功能点的 `原型图` 段写 `IMG-xx` 编号即可；图片识别细节由对话与归档清单（对话中输出）承载。

## 六、待确认项触发场景与输出模板

> **统一标准见主规则 §1.6**。本节仅列出图片场景下的具体触发条件；输出格式严格按 §1.6 的 5 列结构（`编号 / 问题类型 / 涉及范围 / AI 当前处理 / 待用户确认`）。

**图片场景下的触发条件**：

- 图片间冲突（A 图必填、B 图该字段未出现）
- 图片与文字补充冲突（图片必填、文字非必填）
- 图片模糊 / 看不清标签
- 控件类型歧义（看起来既像输入框又像下拉）

**输出模板（按 §1.6 通用 5 列结构）：**

| 编号 | 问题类型 | 涉及范围 | AI 当前处理 | 待用户确认 |
|---|---|---|---|---|
| Q-01 | 图片冲突 | 字段「仓库编号」/ IMG-01 vs IMG-02 | 按 IMG-01 的"必填"暂处理 | 最终必填规则以哪张图为准？ |
| Q-02 | 图片模糊 | 字段「状态」/ IMG-02 | 暂按"未识别到"处理，约束规则留空 | 请提供含"状态"列的清晰列表截图 |
| Q-03 | 控件类型歧义 | 字段「仓库类型」/ IMG-01 | 暂按"文本输入框"处理 | 是文本输入框还是下拉选择？请提供清晰截图或文字说明 |

→ **位置/性质**：与图片绑定表、识别结果、归档清单、合理化建议并列，**严禁写入 PRD 正文文件**（详见 §1.6）。

## 七、合理化建议（如实识别 + 优化提醒）

AI 在"如实记录截图"的同时，对明显可优化的点给出补充建议；建议**不改变识别结果**，用户自行决定是否采纳。

**硬约束：**

- 建议**不改变识别结果**；
- 每条建议**必须写明理由**，否则不输出（避免无依据的主观建议）；
- 与"待确认项"严格区分：待确认是**必须澄清才能继续**的冲突；合理化建议是**可选改进**；
- 无可建议时直接输出`无。`，不凑数。

**触发场景：**

| 建议类型 | 典型场景 |
|---|---|
| 必填优化 | 关键业务字段（编号、名称等主键性字段）图上非必填 |
| 默认值优化 | 默认值与日常业务习惯不符（如状态筛选默认"全部"，但用户日常更关注"启用"） |
| 长度/格式限制 | 文本框无最大长度、无格式约束 |
| 控件类型优化 | 金额字段用普通输入框（建议数字输入框）、多选场景用单选等 |
| 高频字段缺失 | 基础资料无"创建时间""创建人"，下游审计追溯困难 |
| 操作按钮缺失 | 状态类数据列表缺少"启用/停用"、基础资料列表缺少"导出" |
| 查询条件缺失 | 列表数据量预计较大但无"状态""创建时间"筛选 |

**输出模板：**

| 建议类型 | 涉及字段 / 位置 | 截图现状 | 建议 | 理由 |
|---|---|---|---|---|
| 必填优化 | 仓库编号 / IMG-01 | 非必填 | 建议改为必填 | 业务主键，缺值会导致下游数据关联异常 |
| 默认值优化 | 状态筛选 / IMG-02 | 默认"全部" | 建议默认"启用" | 日常运营更关注启用中的数据，可减少筛选步骤 |
| 字段缺失 | 商品管理列表 / IMG-03 | 无"创建时间"列 | 建议补充"创建时间"列并支持排序 | 基础资料通常需按时间审计追溯 |
