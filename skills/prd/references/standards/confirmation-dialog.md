# 二次确认标准规则块

> 用途：作为 PRD 场景中"二次确认提示框"写法的统一口径来源（**仅规定二次确认弹窗的「确认」路径文案**）。
> 适用范围：prompt 模板、skill、rule、PRD 正文编写说明。
> 说明：查询/查看类功能不适用本规则。
>
> **配套规则**：
> - **取消路径句式**（按 UI 类型分流）见 [prd-template-structure.mdc §4.3.2](../../_rules/prd-template-structure.mdc)：弹窗类用 `用户点击「取消」，系统关闭弹窗，不执行任何操作。`；页面类用 `用户点击「取消」，系统返回<X>列表，不执行任何操作。`
> - **正向路径必含 2 要素**（成功反馈文案 + UI 落点）见 §4.3.2
> - 二次确认弹窗是 §4.3.2 双路径中的「确认」路径的入口前置步骤

## 标准规则

• 查询/查看功能：不记录操作日志，不触发二次确认。
• 其他需留痕动作：必须记录操作日志。
• 是否触发二次确认：按动作类型输出，不得统一写成单一句式。

### 1. 新增、编辑

• 适用范围：仅能操作单条数据的新增、编辑类动作。
• 标准文案：`系统弹出二次确认提示框：确认提交该<业务名称>？`

### 2. 启用、停用、关闭、发货、标记发货、删除

• 适用范围：可操作单条或多条数据的动作。
• 单条文案：`系统弹出二次确认提示框：确认<功能名称>该<业务名称>？`
• 多条文案：`系统弹出二次确认提示框：确认<功能名称>所选<业务名称>？`

### 3. 签收、收货、上架

• 适用范围：仅能操作单条数据的动作。
• 标准文案：`系统弹出二次确认提示框：确认<按钮名称>该<业务名称>？`

### 4. 发布、发布到门店、改价格、改价

• 适用范围：可操作单条或多条数据的下发或改价动作（如总部「发布到门店」、商品库「改价格」、门店商品「改价格」）。
• 单条文案：`系统弹出二次确认提示框：确认<功能名称>该<业务名称>？`（示例：`确认发布到门店该商品？`、`确认改价格该商品？`）
• 多条文案：`系统弹出二次确认提示框：确认<功能名称>所选<业务名称>？`（示例：`确认发布到门店所选商品？`、`确认改价格所选商品？`）
• 也可在「业务名称」前补语义助词形成自然句（如 `确认将该商品发布到门店？`、`确认提交该商品价格？`），但全文必须统一一种句式，避免单/多条混用不同模板。

### 5. 导入、导出（提交确认）

• 适用范围：批量数据进出场景的提交动作；导入因影响落库故触发二次确认，导出按业务需要决定是否触发。
• 导入文案：`系统弹出二次确认提示框：确认提交本次导入？`
• 导出文案（若触发）：`系统弹出二次确认提示框：确认按当前筛选条件导出？`

### 6. 复制

• 适用范围：仅能操作单条数据的动作。
• 标准文案：`系统弹出二次确认提示框：确认复制该<业务名称>？`（示例：`确认复制该价签？`、`确认复制该条形码？`）

### 7. 业务名称定义

• `业务名称` 指当前操作对象名称，需按实际业务替换。
• 常见示例：`商品`、`订单`、`出库订单`、`退货单`、`库区`、`仓库`、`账号` 等。

## 写作要求

• 二次确认文案应写入 `用例规则` 的 `操作流程：` 中。
• 若当前动作支持勾选单条与多条数据，必须分别说明单条和多条文案。
• 若当前动作仅支持单条，不得写多条文案。
• `功能名称` 通常指按钮或动作名称，如：`启用`、`停用`、`删除`、`关闭`、`发货`。
• `按钮名称` 通常指页面实际操作按钮，如：`签收`、`收货`、`上架`。
• 文案中的 `<业务名称>` 必须替换为具体对象，不得直接保留占位符。

## 示例

• 仓库管理-新增：`系统弹出二次确认提示框：确认提交该仓库？`
• 库区管理-启用（单条）：`系统弹出二次确认提示框：确认启用该库区？`
• 库区管理-启用（多条）：`系统弹出二次确认提示框：确认启用所选库区？`
• 商品管理-上架：`系统弹出二次确认提示框：确认上架该商品？`
• 商品库-发布到门店（单条/多条）：`系统弹出二次确认提示框：确认将该商品发布到门店？` / `确认将所选商品发布到门店？`
• 商品库-改价格（单条/多条）：`系统弹出二次确认提示框：确认提交该商品价格？` / `确认提交所选商品价格？`
• 商品库-导入：`系统弹出二次确认提示框：确认提交本次导入？`
• 价签管理-复制：`系统弹出二次确认提示框：确认复制该价签？`
