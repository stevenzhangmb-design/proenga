# ⭐ 用户主用模板 2/2：PRD-only 主流程（无原型）

> 🎯 **核心定位（v1.0 / 2026-06-06）**：
> 本模板是 **PRD-only 生成器主流程**——**没有原型，只要 PRD 文档**的场景下使用。
>
> 👤 **你只需要看 2 个模板**（按你的需求选其一）：
> - ⭐ [prototype-prd-prompt-template.md](../../../pm-design/prototype-prd-prompt-template.md)（原型+PRD 联合）：要画原型时用
> - ⭐ **本文件**（PRD-only）：只要 PRD 时用
>
> 其他 `prototype-template.md` / `annotation-templates.md` / `_rules/*` 等都是 🤖 **AI 内部自用**，你不用读。
>
> **本模板的触发场景**：
> 1. **现有系统已有 UI**：你已经有截图（实际系统/竞品），只想生成标准 PRD 文档，不需要可点击原型
> 2. **PRD-only 增量更新**：在现有系统上改一点东西，只要 PRD 描述（不重画原型）
> 3. **外部协作 / 监管申报 / 内部评审**：协作方只要 PRD 文档（不要原型）
> 4. **新人学习**：理解"一份完整 PRD 提示词长什么样"的样本
>

【AI 场景识别铁律】（必先识别再动手）

按以下顺序判断本次属于哪种场景：

1. 用户勾选了【场景选择】→ 直接按勾选执行
2. 用户填了 4-A 现有模块菜单路径 + 5-A 改动描述 + **无截图** → 场景 A（文字增量）

【各场景的产出顺序铁律】

- **场景 A 文字增量**：① 读懂改动描述（可选读旧 PRD 文件）→ ② 在对话中文字复述对改动的理解（如「您是要在 X 模块的 Y 弹窗加一个 Z 字段，文本输入框、非必填、长度 1~200，对吗？」）→ ③ 等用户回「确认」/「修正 X」→ ④ 写**增量 PRD**（仅 §4 新增/修改部分，旧功能点用「详见旧 PRD §x.y.z」引用，标题标「v1.X 增量：xxx」）
- **场景 B 截图驱动**：按 [standards/image-recognition.md](../standards/image-recognition.md) §5 输出 5 段对话辅助（图片绑定表 → 识别结果 → 归档清单 → 待确认项 → 合理化建议 → PRD 正文）

【AI 如何解读用户输入】（用户侧各项的语义与默认行为）
- 1) 需求名称：作为 PRD 标题、版本变更表「变更内容」、原型 HTML title
- 2) 部署地区：决定日期格式 / 币种 / 时区 / 字段语言；BR 必出葡语 + DD/MM/YYYY + BRL；CN 出中文 + YYYY-MM-DD + CNY；其他地区进【待确认项】
- 3) 背景与核心问题：填入 PRD §1 「核心问题」与「建设目标」
- 4-A) 系统视图与角色：系统视图清单 + 角色清单；前置条件②的「具备权限」句式由 AI 按菜单路径自动生成
- 5-A) 菜单结构与功能点：用户按 `菜单路径：功能点1、功能点2…` 给出；冒号前=菜单路径，冒号后=功能点列表（顿号分隔）；原样落盘，禁止合并/拆分/上提/下沉/改名/重排序
- 4-B/4-C) 现有模块菜单路径：用于 PRD 「§4 位置」字段 + 增量引用基线
- 5-B/5-C) 改动描述：解析"加 / 改 / 删"的关键动词，对应 PRD 增量内容范围
- 图片输入区：每张截图的绑定关系（图片编号 → 系统视图/菜单/功能点）+ 用途/识别重点/补充说明；模板见 [standards/image-recognition.md](../standards/image-recognition.md) §2
- 8) 字段补充规则：用户只补图片/原型识别不到的业务规则——唯一性约束 / 默认值业务含义 / 错误提示文案 / 失焦或提交校验 / 字段级权限；字段骨架（名称/类型/必填/默认值）由 AI 从原型 HTML 或截图提取
- 9) 消息通知清单：用户只列**需要发消息**的功能点，格式 `<系统视图>-<系统菜单>-<末级菜单>-<功能点名>`；**未列出=无**；AI 不自创、不补全；列出的按 §4.6 35 类标准模板自动套接收人/标题/内容
- 10) 非功能要求：性能 / 安全 / 稳定性；不填 AI 用通用默认模板兜底
- 11) 目标与成功标准：填入 PRD §1 「成功指标」；不填则写"本期未提供量化指标"

【增量 PRD 写法铁律】（场景 A 文字增量用）

- 标题：标「v1.X 增量：xxx」格式
- §1 开发目的：仅写本次增量目标，背景一句话引用「详见旧 PRD §1」
- §2 版本变更表：加一行 v1.X，变更内容用动词领起说明本次加/改/删
- §3 术语：仅本次新增/修改涉及的术语
- §4 功能需求：**仅写新增 / 修改的功能点**；未变化的功能点用「详见旧 PRD §x.y.z（v1.0-基线版）」引用占位
- 字段规范：仅列新增/修改的字段，未变化的字段写「详见旧 PRD 同节字段规范」
- 用例规则七项：仅写本次有变化的项；未变项写「同旧版」
- 操作日志：新增功能点必出，修改不变化的操作日志不重抄

【AI 必须遵守的铁律】（口径以 prd-template-structure.mdc 为唯一标准）
请按结构化 PRD 输出（Markdown），并严格遵守以下铁律：
- 章节顺序固定为 4 章：1 开发目的 / 2 版本变更 / 3 术语 / 4 功能需求；**严禁**另起「5 功能点明细」章节，功能点直接挂在第 4 章对应末级菜单下（`##### 4.4.x.y` 下紧跟 `###### 4.4.x.y.z` 功能点）
- §2 版本变更表 4 列固定：`版本 / 日期 / 变更人 / 变更内容`；版本号 `vX.Y`；日期 `YYYY-MM-DD`；变更内容含具体模块名 + 动词领起，多条用 `；` 分隔（详见 §1.4）
- §3 术语章节标配（按 PRD 涉及动作必出现）：软删除（含删除）/唯一性校验/状态机/二次确认弹窗/异步任务/双消息/回显/条件必填；功能点正文用 `（详见术语：<X>）` 引用（详见 §1.5）
- §4.3 业务流程图：用 mermaid（flowchart/stateDiagram-v2/sequenceDiagram 按场景选）；节点形状约定（开始结束圆角/动作矩形/判断菱形）；泳道用 `subgraph` 模拟；单图 ≤ 20 节点；**禁**纯文字描述无 mermaid（详见 §2.1）
- **「待确认项」遇 5 类触发场景必输出**（§1.6）：① 图片相关 ② 业务规则缺失 ③ 菜单/功能点不匹配 ④ 模板库不命中（§3.1.4/§3.1.5/§4.6.5）⑤ 多种合理解读；统一 5 列：`编号 / 问题类型 / 涉及范围 / AI 当前处理 / 待用户确认`；编号 `Q-01、Q-02` 顺序；**严禁臆测/推托/自创**；仅作对话辅助输出，**严禁写入 PRD 文件**；用户答复后更新 PRD 并移除该项
- 系统视图、菜单、功能点名一律取用户给出的真实命名
- 多系统视图分端只在用户明确要求时输出，否则按单系统视图成文
- 结构解析铁律：`菜单路径：功能点1、功能点2…` 输入中，冒号前仅菜单路径，冒号后仅功能点；原样落盘，禁止合并/拆分/上提/下沉/改名/重排序
- 字段规范仅收录数据字段；按钮、操作链接、底部操作区一律不进表，由用例规则-操作流程承载
- **字段规范分块标题禁臆造**（§3.1.6）：分块标题（如 `**1、基本信息**` `**2、价格库存**`）必须有截图依据（弹窗 Tab / 页面分组 / 折叠面板等），分块名一字不易取自截图真实文字（基础信息 ≠ 基本信息）；截图无明显分组特征时直接平铺单表，**禁止**自创 `**N、xxx**` 加粗序号分块
- **日期时间显示格式按部署地区**（§3.1.5）：UI 展示层默认 CN→`YYYY-MM-DD HH:mm:ss`、BR→`DD/MM/YYYY HH:mm:ss`、US→`MM/DD/YYYY hh:mm:ss AM/PM`；数据存储/日志层固定 ISO 8601 `YYYY-MM-DD HH:mm:ss`。**AI 开始写 PRD 前必须主动询问用户部署地区**（"本次 PRD 是面向中国还是巴西/其他地区？"）；若用户输入含 `巴西`/`Brasil`/`BRL`/`NCM`/`CEST`/`CFOP`/`葡语` 等线索可直接判定 BR；未问 / 未确认即按默认输出 = 违规
- 字段规范采用**五列表头**：`字段名称` `类型` `是否必填/必选` `默认值` `约束规则`（详见 prd-template-structure.mdc §3.1）
- **约束规则列禁写**：通用安全约束（`防 SQL 注入`/`防 XSS`/`防注入` 等→PRD 顶部 NFR 统一）、校验逻辑包装（`失焦或提交时...`/`则拦截...`/`系统不落库`→属校验规则/提示消息）、IMG 引用（`以 IMG-XX 为准`→ `.2 原型图`段）、推托语（`按业务定`/`以实现为准`/`按截图实际值`/`按业务配置`）、UI 反馈（`红字提示`/`拦截保存`）、校验条件前缀（`仅在<X>时为必填`）。**只写具体业务/行业标准约束本身**（如 `11 位纯数字；以 1 开头`、`长度 1~100 字符`、`同货主下唯一`）。
- **默认值列写法**（§3.1.5，2026-06-28 定）：默认值列 = "字段打开默认显示什么，一律以原型为准"。**新增类** 3 种——有默认值写默认值（含单选默认选中如"无物流发货"）/ 无默认值·有占位写**占位原文一字照原型**（请选择/请输入<字段名>，**不设统一标准文案**）/ 无默认值·无占位写 `空`/`无`；**编辑·查看类** 一律写 `回显`。形态无关（PC/APP/小程序/H5/网站同）。**禁写** `按业务定`/`按业务配置`/`按截图实际值`/`以 IMG-XX 为准` 等推托语；**禁 `空（显示"X"）` 旧包装**。
- 用例规则七项锁定顺序与文案：前置 → 流程 → 后置 → 校验 → 提示消息 → 消息通知 → 操作日志

- 后置条件按 15 类标准句式（§4.2.2）：每条必含「结果状态 + 可见位置」；删除类只写 `<对象>从<模块>列表移除（详见术语：软删除）`，不重复抄软删除全文；§3 术语章节须定义「软删除」条目；多条同样按 `1、2、3、` 分条

- 二次确认按动作类型分句式（详见 [standards/confirmation-dialog.md](../standards/confirmation-dialog.md)）

- 列表名称带模块全名（如"仓库管理列表"）；二次确认/配置类弹窗操作流程必写**正向 + 反向双路径**——正向必含成功反馈文案 + UI 落点；反向**按入口 UI 类型分流**：弹窗类用 `用户点击「取消」，系统关闭弹窗，不执行任何操作。`，页面类用 `用户点击「取消」，系统返回<X>列表，不执行任何操作。`（详见 §4.3.2）
