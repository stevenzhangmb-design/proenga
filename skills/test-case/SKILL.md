# Test-Case Skill — 测试用例

## 触发场景

| 触发 | 示例 |
|---|---|
| 原型确认后 | "原型 OK 了，出测试用例" |
| 显式指令 | "生成测试用例 / 出测试用例 / 给 QA 的测试文档 / 写测试场景" |
| 同步更新 | "原型改了，测试用例更新一下" |

## 输入（单一真理源）

1. **prd-data.json** —— 字段规范 + 用例规则
2. **原型 HTML**（执行参考）

## 输出

单文件，前缀 `测试用例`，输出目录 / 命名 / `.docx` 同步均按公共约定 [../_shared/downstream-skill-conventions.md §1](../_shared/downstream-skill-conventions.md)。

## 与 prd-data.json 的映射规则

> 字段语义以 schema 真理源 [../pm-design/prd-data-schema.md](../pm-design/prd-data-schema.md) 为准；下表只做 schema 字段 → 测试用例的映射，不重定义字段语义。

| prd-data.json 内容 | 对应测试用例 |
|---|---|
| `field_specs[].required = "是"` | 必填校验用例（留空 → 失焦红字）|
| `field_specs[].constraint` 含范围 | 边界值用例（最小/最大/超限）|
| `field_specs[].constraint` 含「同 X 唯一」 | 唯一性校验用例 |
| `field_specs[].constraint` 含正则 | 格式校验用例（合法 / 非法 / 边界格式）|
| `use_cases.preconditions` | 前置条件用例（未登录 / 无权限 / 业务前置不满足）|
| `use_cases.operation_flow` 每步 | 分步操作用例 |
| `use_cases.postconditions` | 结果验证（列表变化 / 状态变化 / 数据落库）|
| `use_cases.validations` 每条 | 业务前置校验用例（拦截 + 提示）|
| `use_cases.prompt_messages` | 字段级提示文案验证 |
| `use_cases.message_notifications` | 通知触达验证（接收人 / 渠道 / 内容）|
| `use_cases.operation_log` | 操作日志写入验证 |

## 同步更新机制

按公共统一同步 SOP [../_shared/downstream-skill-conventions.md §2](../_shared/downstream-skill-conventions.md)：test-case 是该 SOP 的**唯一增量例外**——因测试用例按功能点逐条编号（TC-xxx）、耦合度低，可【**增量增删变更的用例**】而非全文重写；仍需在文档头追加变更日志列出变更点。

## 适用产品形态

任何产品形态都适用。按业务对象自动生成对应用例。

## 规范遵守

遵守 [pm-design/v1-master-spec.md](../pm-design/v1-master-spec.md) 的单一真理源原则。
