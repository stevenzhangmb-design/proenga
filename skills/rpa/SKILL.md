# RPA · 登录真系统 → 1:1 抓取工具链

> 🔴🔴🔴🔴 **先研究后建议铁律（2026-11-13 用户明令「工作底线」· 最高优先 · 随包 · 所有 skill 通用）**：给用户任何决策建议前，必须先研究竞品和行业标准系统、本系统现状、行业规范和法规原文，建议里写明依据和证据等级；研究不够就说“还不能建议，缺……”；结论和之前的建议不同，第一句就更正。全文见 [../_shared/research-before-advice.md](../_shared/research-before-advice.md)。

> **何时用**：用户让「学别的系统 / 复刻这套后台 / 抓某系统的 UI 或功能」，或需要**真值**（真实尺寸/字段/组件/交互）来 1:1 还原、抽竞品规范、生成测试基线时。**登录真系统，把每个模块、每种页面、每个组件的真实 DOM + getComputedStyle 逐个量下来**，作为真理源。禁"对个大概"、禁凭记忆臆造。
>
> **零依赖**：只用 Node 18+ 自带的 `fetch` / `WebSocket` + 本机 Chrome/Edge 的调试协议（CDP）。不需要 playwright/puppeteer。**它是维护者/复刻用的工具，不是客户运行时依赖**（不打包进客户依赖）。
>
> 跨工具通用（Claude Code / Cursor / Codex / OpenClaw 都能跑 `node`）。图形验证码 **AI 自己截图识别**；仅邮箱/短信码需用户给。

## 🔴 先看这条：Chrome 活不过一条命令（2026-10-13 根治·为此折返 8 次）

**现象**：`node launch.js … 9222` 明明打印「✅ 已启动」，紧接着 `node act.js …` 就报「连不上调试 Chrome」。前台、后台、换端口、换 profile 全试过，都一样。

**真因**：**`launch.js` 这个 node 进程一退出，它启的 Chrome 就被回收了** —— AI 工具跑命令时整个进程树会被收掉，`detached + unref()` 在 Windows 作业对象下不管用。
所以「先跑 launch.js，再跑 act.js / extract.js」这种**跨命令共用一个 Chrome 的用法，在 AI 工具里必然失败**（在你自己的终端里手敲则没问题——那里 Chrome 能常驻）。

**现在怎么办**（已在 `_cdp.js` 里根治，不用你操心）：
- **每个工具连不上就自己拉一个 Chrome**，随本进程存活、结束自动收干净。`extract.js` / `formextract.js` / `extract-spec.js` / `derive-config.js` / `freeze.js` 这类**一条命令跑完**的工具，现在直接跑就行，**不需要先 launch**。
- ⚠️ 但 **`act.js` 的 `goto` 和 `eval` 是两条独立命令、各自一个 Chrome**，第二条看不到第一条导航到的页面。**要「打开某页再取值」请改用**：
  `node ../pm-design/p.js <源.json> deliv x --file <那个.html> --ask "<JS表达式>"`
  （p.js 在同一个进程里完成 打开 + 求值，一条命令出结果）
- `launch.js` 仍然有用：**你想要一个人工可见、长期开着的浏览器**（登录真系统、过验证码）时用它，在你自己的终端里跑。

## 标准步骤

```bash
# 1) 自启动 Chrome（调试模式常开·会话持久·独立进程），开到登录/目标页
node launch.js "https://目标系统/login" 9222

# 2) 截图看当前页（AI 直接读这张 png）
node shot.js login.png 9222

# 2b) 图形验证码：用 captcha.js 抽成【小而清晰】的图再读（比读整页大截图稳很多）
node captcha.js cap.png 9222        # 优先抽验证码<img>的 data:URI(像素级)·抽不到则元素紧裁3×放大
#   → AI 读 cap.png 识别 4~6 位字符。小图躲开"图像请求过多"限制、识别率高。
#   验证码一次性、读→填要连贯（中间别刷新页面，否则它会换一张）。

# 3) 登录：账号用 act.js fill；密码/验证码走一次性小脚本读环境变量填，别写进文件
node act.js fill "账号占位符::用户名" _.png 9222
#   （密码/验证码：写个一次性脚本读 env 填，避免落文件——见凭据纪律）

# 4) 逐模块逐页导航 + 截图
node act.js click "菜单名" step.png 9222
node act.js goto  "https://目标系统/xxx/list" list.png 9222

# 4b) 点不动（el.click()/click 没反应）→ 用硬件级点击；坐标**直接照截图量**
node act.js tap  "820,530" step.png 9222      # 也可传 CSS 选择器
node act.js win  "1680x1000" _.png 9222       # 嫌视口小就放大真实窗口（持久）
#   ⚠️ 不用再为 dpr 换算：_cdp.js 的截图已统一输出 **CSS 像素**（clip.scale=1/dpr），
#      所以「截图上量到的坐标 == tap 坐标」。
#   §2026-10-10 血泪：以前截图是设备像素(dpr=2 → 2074px 宽)、而 Input.dispatchMouseEvent 收 CSS 像素
#      (视口 1037px)，照截图量的坐标每次都点在 2 倍远的地方 —— 症状是"点了没反应"，
#      我误判成「这个 POS 按真实指针事件判定，CDP 打不进」，还为此写了 touch（没用），白卡一整轮。
#      **点不动先对一下 innerWidth 和截图宽度，别先怀疑对方框架。**

# 4c) 页面白屏 / 行为不对 → 直接看它的 JS 报错，别二分注释代码
node act.js console "https://目标系统/xxx" _.png 9222   # 打开并打印 exception + console.error

# 5) 抽结构 + 计算样式（真值落 JSON）
node extract.js     goods-list.json 9222     # 列表/筛选/查询页：筛选控件/列/按钮/令牌
node formextract.js goods-add.json  9222     # 新增/编辑/查看：字段/label/列数/行距/底部按钮
```

## 像素级冻结抓取（freeze —— 第①步「跟真系统一模一样」，与 extract 是两种目的）

> **freeze = 把真系统那一刻的【真实 DOM + 全部资源】原样冻成"任意浏览器双击就开的通用单 .html"**，逐像素等于真系统、断网自洽。因为是冻结、不是重画，**根本不存在"发现一个改一个"**——一次就是 100%。零依赖（Chrome 内置 CDP 快照 + 本地 `mhtml2html.js`，无 npm 包、无 AGPL、可打包上 GitHub）。

```bash
# 场景①：我登录真系统，逐页冻（launch 起 Chrome→我完成登录→逐页 freeze）
node launch.js "https://目标系统/login" 9222
node freeze.js goods_list.html "https://目标系统/goods/list" 9222   # 给 url 先导航再冻
node freeze.js current.html                                          # 不给 url = 冻当前页
#   --keep-mhtml 额外留一份 .mhtml

# 场景②：用户直接发链接 → 一条命令抓
node freeze.js 目标页.html "https://用户给的链接" 9222

# 已有 .mhtml 快照 → 直接转通用 .html（不用重新登录抓）
node mhtml2html.js 01-列表.mhtml 01-列表.html
```

**freeze vs extract——两种目的，别混**：
| | freeze（+mhtml2html） | extract / formextract |
|---|---|---|
| 产出 | 像素级**冻结件**（单 .html·一模一样） | **结构+计算样式 JSON**（真值源）|
| 用途 | 「跟真系统一模一样」的成品·对照真相 | 提炼默认规范 + 驱动装配再生成对齐 |
| 可编辑/标注 | 否（静态冻结） | —（喂装配器生成可编辑原型）|
| 保证度 | **天生 100% 逐像素** | 逐值真值·靠机器闸逼装配件对齐 |

> **验收硬证据**：冻结件必须**断网也能完整渲染**（路由拦截一切 http(s) 后截图仍逐像素完整）→ 证明图片/CSS/字体真内联成 data:URI，不是靠联网。残留的 http 外链多是导航 `<a href>`/JS 里的 API 地址，静态件无需。

## 抓全每一种页面（一个都不能少）
查询/筛选 · 列表 · 查看/详情 · 新增 · 编辑 · 删除(确认弹窗) · 导入 · 导出 · 审核/审批 · 批量操作 · 打印/标签。
每种都 `extract`/`formextract` 一遍，把真值逐条对进原型（控件高宽、字号、配色、圆角、列顺序、占位符、间距、弹窗宽）。

## 凭据与验证码纪律（强制）
- **图形验证码**（页面上扭曲字符图）：`shot.js` 截图后 **AI 自己识别**填入，不用问用户。
- **邮箱/短信验证码**：发到用户私人邮箱/手机，屏幕上没有 → 只有这种需要用户给。
- **账号/密码**：只用于登录，**绝不写进任何文件、绝不回显**；密码走环境变量在一次性脚本里填、用完删。
- **真系统只看不提交**：抓取全程只读——**绝不点「提交/保存/删除」等会改真系统数据的按钮**（如出库单「提交」会真发货）。只到弹窗/表单渲染出来就抓、然后离开。
- 抓到的**客户系统真值 JSON 属本地资产**，含客户标识（域名/模块名）→ **不进公开包**（`../pm-design/learned-specs/<客户系统>.json` 本地留存、公开发布时排除）。

## 产出去哪
- 真值 JSON → `../pm-design/learned-specs/<系统>-<日期>.json`（该系统的复刻真理源）。
- 复刻完原型后，再 `extract` 一遍原型自身，**对照 learned-specs 逐条核对，不等即改**；或用 `../pm-design/qa/fidelity-audit.js`（真系统快照 ⇄ 复刻件逐维机器 diff）跑到全绿=1:1。
- 默认 UI 规范的实测数值 → 沉淀进 `../pm-design/system-design-spec.md`（§2.0 全组件真值总表·§5.4 RPA 全量实测）。

### 🔴 抽真值【直接抽活页面】，不要从冻结件抽（2026-10-30 实测确立）
两条路产出的值**不等价**，而且差异是静默的：

| | 做法 | 值准不准 |
|---|---|---|
| ✅ **抽真值** | `tokens.js <线上URL>` 直接读活页面 computed | **准**（实测按钮 `border: 1px solid rgb(51,99,255)`，与真系统一致）|
| ⚠️ 从冻结件抽 | 先 `freeze` 再对冻结件 `tokens` | **可能失真**（同一按钮抽成 `2px outset`）|

**为什么**：冻结件是"DOM + CSS 文本"重新渲染出来的，只要重建 CSS 时丢了声明，computed 就变。
2026-10-29 查实的那个坑（`cssText` 对「简写 + `var()`」往返不保真）就属于这一类 ——
**冻结件看着正常、能渲染、能抽值，值却是错的**。

**所以分工是**：`freeze` 负责**像素级留档**（断网自洽、可回看、可做基线快照）；
**抽真值一律走活页面**。两者都要，但别拿冻结件当真值源。
（`freeze.js` 的 CSS 失真已修成取原始文本，但"直接抽活页面"这条路本来就不经过这个风险。）

### 为什么真值必须带上下文（2026-10-29 实测·踩了一整轮才明白）
从 55 个真实界面抽出的老真值里有 **41 处"分歧"**。按【系统 × 变体】拆开后发现：**没有一处是两个系统的差异**，全是抽法自己制造的噪音，三个来源 ——

1. **外层和内层混收**：`<th>` 自己 padding 是 `8px 0`，它里面的 `.cell` 是 `0 12px`。两个都当"表头"收，一致率自然只有 35%。
2. **不记场景**：列表主表的表头是 `#999`，弹窗里内嵌表的是 `#909399`。这是两种场景的真实不同，不记场景就变成"对不上"。
3. **变体没拆够**：实心钮和文字钮、勾选列和普通列、选中和未选中的勾选框、组合输入框（圆角只圆一边）、卡片式和线条式页签 —— 混成一类就是一半一半的假分歧。

另有两个**污染过往所有结论**的坑，都已在 `tokens.js` 里修死：
- **日历被当成表格数据**：日期选择器内部也是 `<table>`（91 个日期格）。用通用 `th,td` 选择器会把它全抽进来 —— 这就是老报告里"表体一致率只有 4%"的真因。按那种值复刻，表格永远对不上。
- **真系统不是全用 Element Plus**：WMS 出库订单列表是**手写原生表**（`.native-table-wrap` / `th.first-th` / `td.check-box-td`）。只认 `.el-table__cell` 的话，这类页一个表格都抽不到，却不会报错 —— 静默漏抓比报错危险。

**基线对不对的试金池**：拿基线去验**真系统自己**，必须全绿。第一版基线只记"主值 + 前 3 个其他值"，把 55 个真系统页面里的 **46 个判成了红** —— 基线把真系统自己判成不合格，那基线就是错的，拿它卡复刻件只会制造假红。改成「记录该桶出现过的全部取值」后，55 页全绿。
